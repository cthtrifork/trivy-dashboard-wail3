# Decision log

Short records of decisions. Add new entries at the bottom; supersede rather than delete.

| # | Decision | Why |
|---|---|---|
| 1 | Wails v3 (v3.0.0), Go 1.26, plain JS frontend with no build step | Matches the requested stack; no Node needed to build; frontend embedded with `go:embed` |
| 2 | Scans run Trivy in a **podman** container, not a local Trivy install | Requested; keeps the host clean; the Trivy DB lives in a host cache directory (local podman) or the `trivy-cache` volume (remote podman), see architecture.md |
| 3 | Fixtures are for tests and screenshots only; `wails dev` uses real podman unless `TRIVY_SCANNER_FAKE_PODMAN=1` | Maintainer reversed an earlier "fake in dev" design; fixtures are compiled out of production builds |
| 4 | Priorities view ranks with an explainable rule engine (KEV, EPSS, CVSS, attack vector, fix availability) | Goal: ten findings that matter, with a reason shown |
| 5 | VEX assessments stored per image repository in a JSON file; export OpenVEX v0.2.0 | Carries over between scans and tags |
| 6 | Dependency view is a force-directed **graph**, not a tree | Maintainer request; canvas, no library |
| 7 | CI follows Wails v3's own workflow for tests; v2 build-action ideas only where they apply (see `ci.md`) | The cross-platform guide has no test step and targets v2 |
| 8 | Linux amd64 only | Maintainer: "only need to build a Linux binary" |
| 9 | **Fedora/GTK3 variant dropped** | Maintainer cancelled it |
| 10 | Self-update via GitHub releases, SHA-256 verified, user-initiated, off in dev/headless | Wails self-update tutorial; see `self-update.md` |
| 11 | Releases cut by the *Tag and release* workflow (an explicit tag, or Release Drafter's version) | Tags cannot be pushed from the agent sandbox; one-click for the maintainer |
| 12 | Headless use is an SSH tunnel to a loopback listener; no auth layer | Wails server mode has none; exposing it is out of scope (principle 10) |
| 13 | Podman-only servers run the app in a container with `podman-remote` and the host socket, `--network host` | Server has no Go; host network keeps the loopback Host guard |
| 14 | Frontend is **Vue 3 + Vite** with generated Wails bindings, replacing plain JS. Supersedes the "no build step" part of decision 1 and the old principle 15 | Maintainer request, following the Wails v3 notes tutorial and its Vue template. Costs: Node 20.19+/22.12+ is needed to build; `go build` needs `frontend/dist` (placeholder `.gitkeep` keeps `go vet`/`go test` working without it); CI, release and build/docker/headless.Dockerfile build the frontend first. Runtime dependencies are only `vue` and `@wailsio/runtime`; the graph stays canvas. The UI calls `ScanService` through generated bindings (`frontend/bindings`, committed so builds need no wails3 CLI) |
| 15 | VEX author and review-by date are stored per assessment but not exported to OpenVEX; an expired resolved assessment stops hiding its finding | OpenVEX has no statement expiry and its author is document-level. Expiry is a UTC date; the day itself still counts. Expired entries stay on record and are flagged, so a stale "not affected" cannot silently hide a CVE |
| 16 | Releases ship a PGP-signed `.deb` and `.rpm` built with `wails3 tool package` (nfpm), plus the public key. Signing uses nfpm's built-in signer with a key in repo secrets; a release fails if the key is missing | Maintainer request, following the Wails v3 Linux build guide. `wails3 tool sign` was not used: it shells out to `dpkg-sig`/`rpmsign` and passes the passphrase on a command line. Amends decision 8 only in adding formats, still amd64 only |
| 17 | Wails' built-in MCP server (`-tags mcp`) is a dev/test aid only: `make run-mcp`, `.mcp.json`, never in production | It gives an agent unauthenticated control of the UI and `ScanService` (principle 10). `mcp_guard.go` fails `mcp`+`production` builds and CI greps the release binary. In server mode it has no webview, so only `app_info`, `windows_list` and `emit_event` work (checked on beta.34); UI driving needs the desktop build. See `mcp.md` |
| 18 | OpenVEX documents are built, validated and parsed with `github.com/openvex/go-vex` (the library under [vexctl](https://github.com/openvex/vexctl)), not with the `vexctl` module and not by hand | `vexctl`'s Go packages add ~230 modules (Kubernetes, Sigstore) for attest/attach/SARIF features this app does not use; `go-vex` has no extra dependencies. Import reads OpenVEX v0.2.0 only; older layouts (string-valued vulnerabilities) are no longer accepted. Exports were checked with the real `vexctl merge` |
| 19 | Image references, package URLs, package versions, the CycloneDX SBOM and CVSS vectors use libraries instead of hand-written parsers: `distribution/reference`, `package-url/packageurl-go`, `go-deb-version`/`go-rpm-version`/`go-apk-version` (by PURL type) with `aquasecurity/go-version` (the library Trivy uses) for tags and everything else, `CycloneDX/cyclonedx-go` and `pandatix/go-cvss` (v2, v3.0, v3.1, v4.0). Trivy's own types, the podman bindings and the frontend graph/virtual list stay custom | Same reasoning as decision 18: small libraries with almost no transitive dependencies (`go-digest` is the only extra module) replace code that was a heuristic or a re-implementation of a spec |
| 20 | The default Trivy image is pinned by tag **and digest** (`pinnedTrivyImage`), moved by Renovate; a digest-only change is reviewed by a person. The vulnerability DB (`trivy-db:2`) keeps its floating tag | A re-pushed or hijacked image tag would otherwise change the code that parses untrusted images. The DB is rebuilt every few hours, so a pin is only as fresh as the last merged Renovate PR (weekdays only) and scans would miss recent advisories; the maintainer decided to keep the floating tag. Only the fallback image is pinned: the UI's version picker and its newest-tag default are unchanged, and a version the user picks runs by plain tag. The pin applies when the lookup fails or no version is chosen. The image digest was read from the Docker Hub mirror and ghcr.io and was identical on both |
| 21 | Screenshots are never committed to `main`: `docs/screenshots/` is gitignored, rendered in CI and shown in one draft, never-merged PR (`bot/update-screenshots`) | Committed PNGs conflicted with each other and every UI merge produced a bot PR to merge; a long-lived draft PR gives a stable place to look at the images without touching `main` |
| 22 | The pprof endpoint (`-tags pprof`, `make run-pprof-server`) is a dev aid only, like the MCP server | It exposes goroutine stacks, heap contents and the command line without authentication (principle 10). It binds loopback only (a non-loopback `TRIVY_SCANNER_PPROF_ADDR` aborts start-up), `pprof_guard.go` fails `pprof`+`production` builds and CI greps the release binary. See `pprof.md` |
